Private origin

Block Public Access on. Only this CloudFront distribution may read the objects.

Route 53 is not in the data path. It only answers the DNS question. Every request after that goes straight from your browser to the nearest CloudFront edge location, and only cache misses travel on to S3.

Lessons learned

What actually went wrong

The useful part of a hands-on project is the debugging. These came up while building project 1.

Unlisting a domain doesn't free it

After removing a for-sale listing, the registrar's nameservers still served a parked page. Only switching the nameservers to Route 53 fixed it.

Right nameservers, still no site

dig NS showed Route 53, but curl said "Could not resolve host". The hosted zone had no apex A record. Checking each DNS layer separately found it.

The certificate must live in us-east-1

CloudFront only reads ACM certificates from N. Virginia, wherever the bucket is. A cert in another region never shows up in the dropdown.

Test the CloudFront URL first

Checking *.cloudfront.net before touching DNS separates bucket and policy problems from DNS problems.

Try it yourself

Inspect this site from a terminal

# Which nameservers answer for the domain? $ dig NS leapmotion.ai +short # Which IPs does Route 53 return? (CloudFront edge addresses) $ dig A leapmotion.ai +short # Response headers: look for x-cache and x-amz-cf-pop $ curl -sI https://leapmotion.ai
